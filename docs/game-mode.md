## 1. 产品与入口

手机是一只通用无线手柄，Mosaico 负责运行与显示。游戏自行解释标准按键，手机不发送「坦克开火」等专用指令，不投屏、不靠 AI 猜测触摸位置。

入口：「应用 → 我的创作 → 让手机，成为手柄」。点击直接进入横屏，不先选游戏，不显示封面或部署向导。创作、应用中心和作品部署仍走原流程；进入手柄不会自动获取、上传、启动或停止游戏。

## 2. 自动连接流程

1. 进入横屏，隐藏工作坊头部及底栏，沿用当前局域网设备连接。
2. 未连接设备：沿用自动扫描；提供重扫、手动地址和退出。
3. 已连接：自动检查 WebSocket 自动接入能力与当前游戏状态，无「请求控制」按钮。
4. 没有游戏：显示「等待游戏运行」，提供「返回选择游戏」。保持状态轮询；游戏调用 gamepad.open 后自动接入。
5. 游戏可用：建立新会话，立即发送全零输入；收到首次输入回执后显示「控制已就绪」，启用完整手柄。无需编号核对或设备触屏允许。
6. 另一手机占用：显示暂不可用并间隔重查，不抢占。旧连接释放或失联超时后才接入。

已获取的三款 v2 无需重新获取，新固件不再提供 pending 字段，旧确认面板不会出现。开发阶段直接修改应用中心现有 v2 预置源码，不再发布新版本，也不覆盖用户已获取或编辑的作品。v1 和其他未接入 gamepad 的游戏仍需适配。

## 3. 横屏布局

普通 App 仍为暖白竖屏，手柄独立使用石墨色横屏。sensorLandscape 支持左右两种横向握持；按系统安全区避让挖孔与手势区。可用区域不足 600dp × 300dp 时提示退出分屏或横放，不裁切完整手柄。

| 区域 | 内容 |
| --- | --- |
| 顶部 | 当前设备、控制状态、手柄菜单；不展示虚构延迟 |
| 顶部两端 | L2 / L1、R1 / R2 |
| 左侧 | 外侧 LS 与独立 L3，内侧数字十字键 |
| 右侧 | 内侧 ABXY，外侧 RS 与独立 R3 |
| 底部中央 | Select / Start |

ABXY 固定为 Y 上、X 左、B 右、A 下。不按游戏灰显不用的键；仅因连接不可用或菜单打开整体禁用。按钮目标至少 48dp，双摇杆独立触点，按下反馈不改变占位。摇杆保留幅度，右/下为正；左右或上下同时按在固件抵消。

## 4. 菜单、退出与中断

- Start/Select 始终为游戏输入，不冒充手机菜单或系统暂停。
- 手机手柄菜单先释放所有输入，保留有效连接，不发 Start；继续控制不会自动恢复游戏。
- 退出确认只用于离开手柄：释放会话、恢复原方向策略与列表位置，不停止或删除设备游戏。
- 断线/设备变化：立即清零，页面前台且菜单未打开时自动重连，不再要求授权；旧按键不重放。
- 切后台/锁屏：断开会话。返回时停在手柄菜单，选择返回手柄后自动检查，不需要设备确认。
- 旋转/窗口变化/失焦：清零，已有控制时打开菜单，避免触点跨坐标延续；这是操作保护，不是控制权限审批。

## 5. 状态与提示

| 状态 | 用户看到的内容 | 行为 |
| --- | --- | --- |
| 未连接设备 | 连接你的 Mosaico | 自动扫描，可手动连接 |
| 正在检查/同步 | 正在连接手柄 | 禁用输入，自动推进 |
| 未运行适配游戏 | 等待游戏运行 | 返回选择游戏；运行后自动连接 |
| 通道就绪 | 控制已就绪 | 启用标准按钮与摇杆 |
| 通道占用 | 手柄暂不可用 | 约 2 秒重查，不接管其他手机 |
| 旧固件/不支持 | 需要更新固件 | 明确提示，可重新检查；不自动刷机 |
| 连接中断/游戏结束 | 输入已释放，重新检查 | 前台约 700ms 后重连；不自动重开游戏 |
| 手机菜单 | 继续控制、使用帮助、退出 | 无设备授权动作 |

## 6. 实现与安全边界

独立 /ws/gamepad，v=1，access=automatic 能力标记；16 数字按钮 + 4 模拟轴。首次全零状态立即发送；350ms 无新有效状态时设备清空按键与摇杆，input_active=false，但已同步会话的 connected 保持 true；保留会话、序号与物理按键边沿基线，连续 2.5 秒无新有效状态才释放会话并让 connected=false（50ms 检查周期另有调度误差）。手机也以 2.5 秒判断失联，不因一次短暂延迟切换连接页。按键变化立即发，状态最高约 30Hz；未确认状态达到 8 帧时暂停重复心跳，最多 16 帧为按键边沿保留余量，避免积压。固件手柄 socket 启用 TCP_NODELAY；支持手柄的游戏运行期间关闭 Wi-Fi 调制解调器省电，退出后恢复原模式，不写入用户保存的电源配置。保留会话令牌、运行实例、序号与有界顺序边沿。

Lua API 为 gamepad.open/poll/close。poll.connected 在首个有效输入后为 true，短暂抖动不改变它；poll.input_active 区分输入是否新鲜，不提供 pending。短抖动只临时冻结并提示信号弱，恢复后移除临时冻结；不解除手动暂停。保持渲染、轮询和触屏接管。Start 使用 pressed/events，不从安全归零后的 held 自行推导边沿。approve 仅作为旧 v2 的无操作兼容接口保留，新生成游戏不使用。网络任务只更新输入缓存，不调用 Lua 或 UI。

取消物理确认意味着可信局域网内可达的客户端可以直接连接手柄。令牌仅防混用旧会话，不等于鉴权；当前没有 TLS 或安全配对，不能暴露到公网。仍保留单控制者规则，不自动抢占。

## 7. 当前游戏与后续引擎

三款预置游戏：A 开始/重试、Start 暂停/继续；原触控和 EXIT 保留，失联由游戏自身暂停。

- 坦克：方向键/LS 移动转向，A/R1 开火，可组合。
- 飞机：方向键/LS 移动并自动开火，LS 保留幅度。
- 赛车：方向键每次按下换道；LS 越阈值换道，回中后可再次同向换道。

「通用」是统一输入协议，不是任意旧游戏免适配。原有 Hub、通知栏、Dino/Flappy/Bricks 未接收手柄输入。gpSP、gnuboy、Doom、Quake 1 留待后续源码、内存、资源和许可证评估，本轮不引入或分发 ROM/WAD/PAK。

## 8. 自由创作默认双操作

直接输入“生成贪食蛇”或描述一种游戏，即按“触屏 / 手机手柄”双操作要求生成；不用再强调手柄能力。设备是运行与显示主体，手机只发送通用按键，不要求游戏加载引擎。明确要求“仅触屏，不要手柄”时才例外；非游戏工具保持原样。

- 无手机、无 Wi-Fi 时，触屏也须覆盖开始、核心玩法、暂停/继续、重试、EXIT；连接手机后不隐藏触屏入口。
- 触屏与手柄汇入同一份游戏状态/动作处理，按玩法映射方向键/LS、A、B、Start；不要求使用全部按键。连续动作使用长按/模拟轴，离散或回合动作使用按下边沿，不必读取无用的轴值。
- 初始未连接不是断线。仅已连接后失联才暂停、释放动作；可触屏或 Start 继续，重连不自动恢复/重开。
- 准备/帮助页给出 ASCII 操作说明，手机作品简介注明“触屏 / 手机手柄”或“仅触屏”。进入手柄、作品部署和自动连接流程不变。

Agent 源码首行声明三种类型之一：

| 声明 | 用途 |
| --- | --- |
| `-- interaction: game-dual` | 默认游戏，触屏与手机手柄 |
| `-- interaction: game-touch` | 用户明确要求仅触屏的游戏 |
| `-- interaction: app` | 非游戏工具/显示应用 |

生成/编辑保存前，先过原有应用包、Lua 语法和能力检查，再做交互结构检查：触摸读取、EXIT 字符串、pad.open/poll/close、input.connected / input.input_active、按键边沿及 Start 引用；模型使用约定的 pad/screen/input 名称。注释和字符串中的伪调用不计入。遗漏交回现有 Agent loop 完整修复，续写中返回的替代包也不跳过检查；仍沿用最多 8 次模型请求、2 次完整修复等原有预算。

这是“模型分类 + 提示约束 + 结构检查”，不是执行生成代码验证玩法。不能证明热区可点、状态转换正确或模型没有错误分类；不得把校验通过当成设备操作已验收。失败不保存新包、不覆盖已有作品。存储/导入/部署不新增此限制，旧作品保持兼容；需要为旧游戏补手柄时，使用继续创作明确要求保留玩法并增加双操作。

## 9. 原型与验证

主稿为本地交互模拟，不连接真实网络或设备。进入已连接场景演示自动检查后就绪；未连接场景演示扫描，支持等待游戏、不支持、占用、断线、后台和重启状态。屏外观察台仅显示本地按钮与轴，不绘制假游戏画面，不存在「模拟设备同意」按钮。

2026-10-14 本轮只运行 Android 单元测试、构建和覆盖安装，不发起真实模型调用、不刷固件、不运行 UI 自动化。新生成游戏的实际画面、触屏/手柄玩法、断线恢复由用户手动验收；此前预置游戏的实机记录不代表新生成游戏已验收，详见交付记录。
