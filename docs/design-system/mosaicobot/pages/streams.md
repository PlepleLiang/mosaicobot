# 反馈与信息呈现

版本 03。本页替代旧版“首页必须带十一张信息流选择器”的覆盖规则。

## 当前核心

第一版设计先闭合意图、应用、部署、运行、修改，而不是先要求用户选表盘。手机结果卡及设备下方反馈区同时区分：

- 已准备的作品：不等于已传输。
- 已上传的产物：不等于已运行。
- 设备回执：需要身份、版本和首帧 / 行为证据。
- 最后一次回执：必须标明离线 / stale，不冒充实时状态。

原型使用“模拟回执”“本地交互模拟”等文字。所有电量、连接、时间点和运行反馈均为演示，不提供虚构时延、帧率或真实设备遥测。

## 旧信息流如何处理

时钟 / 天气主屏、音乐、相机和 IMU 等已有入口已恢复到原型，通过「应用 → 设备应用」管理，也可从设备主屏直接打开。它们不是新建一级导航，也不是仅写在说明里的占位项。手机返回列表不停止设备，退出原有应用才回到设备时钟首页。

旧稿十一张卡片暂不在当前 UI 实现，不应把旧原型选择器描述成现有固件 API。特别是日程、步数和通知聚合，必须逐项确认数据来源；没有数据时不提供假读数。

## 后续扩展约束

当前“打开 / 退出设备应用”通过应用详情的明确动作触发；正式实现必须为目标设备、应用标识与权限建立受信接口。切换成功以设备回执为准，失败保留旧呈现。不要把亮度、旋转、语言等设置重新命名为“信息流”。
