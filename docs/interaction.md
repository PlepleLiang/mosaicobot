## 1. 当前基线与产品目标

手机负责理解意图、生成 Lua、保存版本和编排部署；Mosaico 是运行主体。主线是「表达意图 → 生成并保存 → 确认部署运行 → 查看设备状态 → 继续修改」。

本地 HTML 是可操作的评审原型，所有模型、连接和设备画面均为模拟；它不是实际 App 或固件的运行证据。原生 App 位于 projects/mosaicobot-android。实际验收以 [验证记录](validation/README.md) 为准。

当前不是无条件自动运行：每个版本首次运行前确认。设备页的「自动运行」暂不可用；Lua 语法检查和手机侧模块限制不是安全沙箱。现有 HTTP 仅适合可信局域网，不具备安全配对与设备端权限隔离。

手机 Agent 与设备 Claw 用明确标签区分。生成错误保留当前作品；用户可以查看源码、修改意图或重试，不伪造成功。手机无需连着设备也可以生成和保存，但必须连接后才可部署。

### 设备

依次为标题、连接卡、能力四宫格、运行授权说明、设备 Claw、折叠的手机 Agent 配置。能力卡说明硬件具有 480×480 屏幕、IMU、Audio、Camera；**当前手机生成只接入屏幕和触摸**。

「管理连接」支持自动发现开关、手动扫描/停止、候选设备切换和手填局域网地址。IP、扫描细节和错误放在管理面板，不占用创作首页。当前无安全配对码，不把接口通过叫作受信身份绑定。

「和设备 Claw 对话」进入独立会话。真实 App 使用 /api/webim/status、/ws/webim、/api/webim/send；先发 WebSocket hello 注册 chat_id，再接收对应会话的 assistant 回复。设备使用自己的模型配置，手机不把自己的 API Key 发送给设备。离开前台断开订阅，不自动重发消息；会话目前仅在进程内保留。HTML 用带“模拟”标识的对话框表达相同角色，不模拟完整 WebSocket。

## 3. 生成、部署与反馈的真实含义

1. 手机请求模型生成兼容现存 cap_lua 的代码；进行语法及保守 lint 检查，保存版本与摘要。
2. 用户查看作品，点击「部署并运行」，确认执行范围与非沙箱提示。
3. 验证设备支持 /api/works；旧固件缺少接口时，在上传前失败并提示更新。
4. 上传到独立的 mb_作品ID_v版本_摘要前缀 目录；不覆盖系统应用，不覆盖已存在且不匹配的目录。同一地址已传输的作品先只读回检。
5. 读回 Lua 和 launcher.json，验证内容；请求 publish，使 app_registry 重载并让 Works 刷新。
6. 请求 start；设备在原有 Works 工作队列中启动 cap_lua，HTTP handler 不直接绘制 UI。
7. 手机轮询同一包 ID 的状态。20 秒内未确认则显示未知，不推断成功，不自动重新发送 start。
8. 前台、非忙碌时约每 2.5 秒刷新当前所选作品状态。切换作品、网络变化、查询失败或进入后台使旧状态失效；不是后台常驻监控。

| 设备返回 | 手机含义 | 不能推断的内容 |
| --- | --- | --- |
| not_found | 尚未发布到 Works | 不证明文件不存在 |
| stopped | 已停止，可再次运行 | 不代表未安装 |
| queued | 设备正在启动 | 不能显示已运行 |
| running | Works 任务正在运行 | 不证明首帧、触摸或业务正确 |
| stopping | 设备正在停止 | 尚未完成停止 |
| failed | 设备运行失败 | 当前未返回完整 Lua 堆栈 |
| 请求失败/断线 | 运行状态待确认 | 不推断设备已停止 |

停止使用独立 stop，而不是 toggle。重复 start 对同一个 queued/running 任务不反转状态，重复 stop 对 stopped/stopping 不反转状态；其他 Works 作品正在运行时拒绝 start，不偷偷替用户停止另一个作品。这不等于跨重启、跨终态的 request_id 幂等事务。

取消表示停止手机等待；若请求已送达，设备可能已经发布或启动。重连后查询状态，不自动停止、删除或重放请求。

## 4. 修改与版本

在当前作品上修改会保存新版本，不覆盖旧 Lua。旧版本可以继续运行；运行新版本前应先停止旧版本。若旧版本不再是当前选中项，可从应用列表打开旧版本再停止，或在设备 Works 操作。

重新运行已有版本不重新调用模型。详情、切换手机标签页、新创作和离开 App 都不自动停止 Mosaico。手机 App 不提供虚假的设备卸载；设备上的安装目录保留。

HTML 只保留一个上一版本参数快照；恢复也必须确认且不能抢占运行中的其他版本。真实 App 保存多个本地版本，尚未提供独立“一键回滚”按钮。原型参数 JSON 不是可部署 Lua 源码，详情明确标为概念契约。

## 5. 局域网与自动连接

真实 App 在启动/回到前台、Wi-Fi 或以太网网络变化时触发有界扫描。优先上次成功地址，否则连接首个通过 Claw 状态及基本 Lua 模块检查的候选。mDNS 与私有 IPv4 探测互补；最多 254 个目标、12 并发、22 秒预算，只读接口，不上传或运行。

自动发现开关持久化；关闭后仍可手动扫描。退出前台停止扫描，网络变化取消旧任务并拒绝旧结果。连接使用绑定局域网的独立客户端，不把模型 HTTPS 流量强制路由至 Mosaico。

HTML 的扫描是 900ms 定时模拟，不访问网络。开关仅控制演示偏好；网络变化测试由评审场景触发，不代表完整复刻 Android 网络监听。

同一局域网不等于 AI 可离线使用，云模型仍需互联网。当前 IP 记忆/接口校验不是密码学身份验证，不保证恶意局域网内的设备身份。安全绑定、撤销、设备端权限 enforce、资源预算、跨终态请求去重及完整运行错误反馈仍需后续建设。

## 7. 与两个工程的边界

Claw 的 Lua/Works 是手机轻量应用的当前路径。核心接口源码见 [Works HTTP](../../projects/esp-mosaico-claw/components/http_server/http_server_works_api.c) 与 [协议说明](../../projects/esp-mosaico-claw/components/http_server/WORKS_API.md)。已有文件接口只负责传输；新发布与启停接口补齐它缺失的生命周期。

Vibe 保留 C/Raylib 原生应用的生成、固定 ESP-IDF 构建、模拟和 firmware system-update 能力。这不是把原生二进制直接装入 Works；也不承诺替换固件后与 Claw 应用自动共存。复杂原生构建仍由可信工作站/服务执行，不假设手机已装完整 SDK。

后续产品级目标为 Device ID/Boot ID、作品版本、请求 ID、运行状态、首帧/行为证据的完整回执。当前 /api/works 协议只核对包 ID 和状态，不能将目标愿景写成已交付能力。
