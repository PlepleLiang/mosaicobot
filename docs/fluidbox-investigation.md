# Mosaico FluidBox 内置应用可行性调查

- 调查日期：2026-10-14
- 状态：仅调查与建议，暂不实施。
- 用户目标：将 FluidBox 做成与 Settings、Weather 同级的 Mosaico 内置应用，点击进入，退出后返回桌面。
- 本次调查未修改业务代码、下载游戏、构建或操作设备。本文件仅保存调查结果，不代表实施或刷机授权。

## 1. 结论

有条件可行。FluidBox 源码完整、依赖相对少，采用 MIT 许可，适合通过源码移植成为当前 Claw 固件中的原生应用。

建议保留现有 Android、Claw、Works/Lua、系统 UI 和 Vibe，复用 FluidBox 的模拟与渲染算法，将硬件访问及生命周期接入现有系统。不安装原版整机固件，不把它包装成网页或 Lua 作品。

## 2. 官方功能与当前版本

官方页面项目为 **Mosaico FluidBox — 掌上的重力流体**，调查时版本为 **0.1.0**。

- 通过倾斜、摇晃和转动设备驱动 1,200 个粒子。
- 五种画面：粒子、液体、海水、岩浆、浮世绘。
- 切换画面时保留当前粒子状态。
- 原版 AI 短按切换画面，运行时 BOOT 短按重置粒子。
- 离线运行，无需扩展模块。
- 官方称支持 ESP-Mosaico V1.0/V1.1/V1.2，使用 480×480 CO5300 屏幕及 BMI270 运动传感器。
- 原版亮度固定为 60%，不支持触摸操作或 OTA 更新。
- 封面是设计效果图，不应作为实机效果验收依据。

**重要：原版发布的是从 0x0 写入的完整 BIN 镜像，会覆盖镜像范围内的原固件和数据，包括 NVS。不得用于当前设备的应用接入。**

## 3. 建议的应用形态

在现有应用列表新增 **FluidBox（流体盒）**，与 Settings、Weather 同级：

1. 点击图标进入流体画面，启动模拟与渲染。
2. 倾斜、摇晃、转动设备驱动流体。
3. 保留五种视觉模式，切换时不重置模拟状态。
4. 提供模式切换、重置和返回操作。
5. 退出时停止计算、释放资源，恢复现有桌面。

这是固件内置原生应用，不需要为此修改手机 App 或现有游戏手柄逻辑。重新进入是否保留上次模拟状态尚未确定，不应擅自加入持久化功能。

## 4. 源码复用和接入边界

### 4.1 复用算法，不搬整套固件

上游 `main/` 已分出 `sim.c`、`render.c`、`imu.c`、`display.c`、`board.c` 等文件。

- `sim.c` / `sim.h`：粒子状态、物理模拟、重置与快照接口。
- `render.c` / `render.h`：五种模式的渲染，当前接口仍与上游分带显示管线耦合，需要适配，不能视为直接可插入的独立库。
- `imu.c`、`display.c`、`board.c`：独立固件的硬件适配，不应直接替换当前驱动和服务。

保留上游及第三方版权声明。项目主体为 MIT；部分屏幕初始化来源涉及 Apache-2.0，具体以仓库 LICENSE、NOTICE 为准。

### 4.2 沿用现有原生应用注册方式

已核查本地 `projects/esp-mosaico-claw/components/mosaic_ui/apps/weather/app.cmake`，Weather 使用 `MOSAIC_APP_LOGIC NATIVE`，具有模块源码、符号、场景和资源包配置。

FluidBox 可沿用现有应用目录、图标及启动机制。模拟和渲染不能在普通 UI 回调中长时间计算；应使用可退出的工作任务，通过现有显示服务提交画面。

### 4.3 复用显示服务，保留系统控制权

已核查 `projects/esp-mosaico-claw/components/display_service/include/display_service.h`，已有独占 RAW 会话、framebuffer 提交、cleanup、退出回调以及允许系统覆盖层的标记。

接入要求：

- 使用系统当前亮度，不强制改成 60%。
- 不重新初始化已使用中的屏幕、I²C 或 BMI270。
- 保留系统返回、下拉栏与 Vibe 官方更新路径。
- 仅在应用前台运行高负载模拟，退出后释放任务、缓冲区和显示会话。
- 与现有独占显示作品正确互斥，不抢占正在运行的作品。
- 不改变现有 Works、聊天、设置、天气及手柄逻辑。

显示服务存在这些接口，不代表移植后自动兼容；系统覆盖层、退出和资源交还仍需实测。

### 4.4 按键与触摸建议

不建议照搬原版 AI/BOOT 按键接管方式，以免冲突现有系统职责。应用版优先提供屏幕模式切换、重置和返回操作；实体键映射应先核对当前职责，再决定是否加入。

## 5. 待验证事项

### 5.1 IMU 数据

当前找到的 `projects/esp-mosaico-claw/components/mosaic_ui/include/mosaic_imu.h` 提供 pitch/roll/yaw 姿态角。上游 `sim_forces_t` 使用重力及摇晃惯性加速度、角速度和角加速度。

实施前需核对现有 BMI270 服务是否能安全提供原始加速度、角速度及正确的坐标映射；不能只接姿态角就宣称完全复现摇晃、旋转效果。

### 5.2 性能与内存

上游 TESTING.md 记录：独立固件、ESP-IDF v6.1、1,200 粒子、QSPI 60MHz、设备平放时的中位帧率如下。

| 模式 | 上游中位 FPS |
|---|---:|
| 粒子 | 59.1 |
| 液体 | 24.1 |
| 海水 | 14.1 |
| 岩浆 | 12.5 |
| 浮世绘 | 33.5 |

上游报告该次检查未观察到重启、TE 超时或传输 underrun，空闲内部 SRAM 为 43,086 字节；同时明确该检查不证明长时稳定或视觉正确性。

这些数据不代表当前 Claw 下的性能。上游双核任务安排及双 PSRAM framebuffer 需要重新评估，不能默认照搬。应测量各模式帧率、内存峰值、系统响应和反复进入退出后的资源泄漏。

### 5.3 固件空间与 SDK

此前只读检查本地已有 `projects/esp-mosaico-claw/build-mosaicobot/edge_agent.bin`：大小 6,597,104 字节，应用槽 8,192,000 字节，剩余 1,594,896 字节（约 1.52MiB）。这是已有构建快照，不是本轮重新构建或设备实时测量，也不能证明 FluidBox 一定装得下。

上游使用 ESP-IDF v6.1；当前项目使用已有 pinned SDK 和 `build-mosaicobot` 配置。适配应遵守当前配置，增量构建确认空间与兼容性，不擅自调整保留分区。

## 6. 后续实施建议与验收

用户当前决定先保存调查，后续再进行需求。以下仅供未来计划使用：

1. 固定上游源码版本，核对许可、显示耦合、IMU 数据和内存分配，提交具体接入计划。
2. 新增 FluidBox 原生入口，接通模拟、五种渲染模式与当前显示/传感器服务。
3. 加入模式切换、重置、退出和失败清理；不添加未请求的后台运行或状态持久化。
4. 运行针对性检查与正确配置构建，测量固件增量；通过必要模拟检查后再经授权进行官方更新与实机验收。

验收重点：点击进入、五种模式与状态连续、倾斜/摇晃/旋转、退出回桌面、下拉栏与亮度、反复进出无泄漏，以及现有应用、Lua Works 和 Vibe 更新链路不受破坏。不得仅凭构建通过宣称实机玩法和视觉验收完成。
